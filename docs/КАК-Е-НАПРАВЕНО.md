# 🦤 Dodo OS — как е направено (пълен дневник)

Този документ описва как е построен **Dodo OS** за OnePlus Nord N100 (BE2013 / **billie2**) — стъпките, решенията и капаните, за да може да се повтори.

---

## Каква е Dodo OS

Privacy-focused Android базиран на **LineageOS 22.2 (Android 15)** за billie2, с вградени:
- 📦 **microG** — Google услуги в sandbox (работи чрез вградената в LineageOS signature spoofing)
- 🎨 **Lawnchair** — Pixel-стил launcher + собствен DODO launcher/dialer/икони
- 🔒 **F-Droid, Aurora Store, Wasted, Duress** — privacy приложения
- 🎬 Собствена **DODO boot анимация**
- 🔐 Криптиране по подразбиране (FBE/f2fs)

> ⚠️ **WiFi статус:** WiFi модулът (`qca_cld3_wlan.ko`) е компилиран и се зарежда, но `hdd_driver_load()` не завършва — WLAN board-data (bdwlan*.bin) липсват от vendor образа. Виж раздел „Известни проблеми" за детайли.

## Как се строи

```bash
# 1. Инициализирай AOSP дървото
mkdir ~/dodo-build/lineage && cd ~/dodo-build/lineage
repo init -u https://github.com/LineageOS/android.git -b lineage-22.2 --git-lfs

# 2. Сложи local manifest
mkdir -p .repo/local_manifests
cp <this-repo>/manifest/billie2-local-manifest.xml .repo/local_manifests/billie2.xml

# 3. Синхронизирай (~90GB, може да отнеме часове)
repo sync -c -j6

# 4. Сложи vendor/dodo/ с APK-тата и конфига
# (vendor-dodo/ от това repo → vendor/dodo/ в AOSP дървото)

# 5. Закачи dodo.mk към device mk
echo '$(call inherit-product-if-exists, vendor/dodo/dodo.mk)' >> device/oneplus/billie2/lineage_billie2.mk

# 6. Приложи кръпките (виж раздел Кръпки)

# 7. Билд (БЕЗ set -u!)
source build/envsetup.sh
breakfast billie2        # НЕ lunch! LineageOS A15 ползва breakfast
mka bacon -j6
```

> ⚠️ **НЕ ползвай `set -u`** в build скрипта — LineageOS `envsetup.sh` разчита на недефинирани променливи и ще се счупи веднага.

> ⚠️ **НЕ ползвай `lunch lineage_billie2-userdebug`** — в LineageOS 22.2 (Android 15) командата е `breakfast billie2`.

## Необходими кръпки

### 1. imsrcsd — crash loop при зареждане

**Проблем:** `/vendor/bin/imsrcsd` (IMS RCS/VoLTE daemon) се срива на всеки ~5 секунди с SIGABRT в `ImsCallInfoService::registerServiceImpl`. Android-овата защита `UPDATABLE_CRASHING` засича това и рестартира системата → телефонът никога не завършва boot.

**Диагноза:** `adb shell logcat -b crash` при черен екран показа безкраен цикъл от imsrcsd crashes.

**Поправка** — редактирай `vendor/oneplus/billie2/proprietary/vendor/etc/init/imsrcsd.rc`:
```
# DODO: imsrcsd неутрализиран — crash loop на всеки ~5s блокира boot.
service vendor.imsrcsservice /system/bin/true
    class main
    user radio
    group radio vendor_qti_diag log inet wakelock
    disabled
    oneshot
```

### 2. LiveDisplay HAL — черен екран след boot

**Проблем:** `vendor.lineage.livedisplay-service.oneplus` е инсталиран, но никога не регистрира AIDL интерфейса `IAntiFlicker/default`. `system_server` чака вечно в `waitForService()` → потребителят никога не излиза от `State: BOOTING` → `FallbackHome` (черен екран).

**Диагноза:** `adb shell dumpsys activity` → `com.android.settings/.FallbackHome`. `adb shell dumpsys user` → `State: BOOTING`. Logcat: `"Waited one second for vendor.lineage.livedisplay.IAntiFlicker/default"`.

**Поправка** — в `device/oneplus/billie2/device.mk` закоментирай:
```makefile
# LiveDisplay (DODO: AIDL интерфейсът никога не се регистрира → блокира boot)
# PRODUCT_PACKAGES += \
#     vendor.lineage.livedisplay-service.oneplus

# Touch (DODO: disabled заедно с livedisplay)
# PRODUCT_PACKAGES += \
#     vendor.lineage.touch-service.oneplus
```

*Загуба:* color calibration настройки и touch gestures — козметично, не функционално.

### 3. AuroraStore uses-library mismatch

**Проблем:** AuroraStore APK декларира `androidx.window.*` библиотеки в манифеста, но те не са в системата → build гърми с uses-library грешка.

**Поправка** — в `vendor/dodo/Android.mk` към **всеки** APK модул добави:
```makefile
LOCAL_ENFORCE_USES_LIBRARIES := false
```
И в `vendor/dodo/dodo.mk`:
```makefile
PRODUCT_BROKEN_VERIFY_USES_LIBRARIES := true
```

### 4. WiFi модул — зареждане при boot

**Проблем:** По подразбиране `CONFIG_QCA_CLD_WLAN=y` (вграден в kernel), но вграденият driver не завършва инициализацията.

**Текуща конфигурация:** `CONFIG_QCA_CLD_WLAN=m` (модул) в `kernel/oneplus/sm4250/arch/arm64/configs/vendor/bengal-perf_defconfig`, зареден при boot с:
```
# device/oneplus/billie2/rootdir/etc/init.target.rc
on post-fs-data
    insmod /vendor/lib/modules/wlan.ko
```

## Boot анимация

LineageOS има официален механизъм за prebuilt boot анимация — ползвай `SOONG_CONFIG`:

```makefile
# vendor/dodo/dodo.mk
SOONG_CONFIG_NAMESPACES += lineage_bootanimation
SOONG_CONFIG_lineage_bootanimation += height width half_res prebuilt_file
SOONG_CONFIG_lineage_bootanimation_height := 1600
SOONG_CONFIG_lineage_bootanimation_width := 720
SOONG_CONFIG_lineage_bootanimation_half_res := false
SOONG_CONFIG_lineage_bootanimation_prebuilt_file := vendor/dodo/bootanimation.zip
```

> ⚠️ `PRODUCT_COPY_FILES` **не работи** за bootanimation.zip — конфликтира с LOS-овия собствен механизъм. Само SOONG_CONFIG работи.

> ⚠️ Ако имаш flashable ZIP с boot анимацията, извади вътрешния файл първо:
> ```bash
> unzip -o -j DODO-BootAnimation-N100.zip "bootanimation.zip" -d vendor/dodo/
> ```

## Флашване

### Нужно
- OxygenOS **11.0.15** (BE81AA) като базов firmware
- Отключен bootloader (`fastboot flashing unlock`)
- `platform-tools` (adb + fastboot)
- DODO recovery image + ROM zip

### Стъпки

```bash
# 1. Рестартирай в fastboot
adb reboot bootloader
# или натисни Vol- + Power при изключен телефон

# 2. Отключи bootloader (само веднъж; изтрива данните)
fastboot flashing unlock
# Потвърди на телефона с Vol+ → Power

# 3. ВАЖНО: billie2 има ОТДЕЛНИ recovery_a и recovery_b партиции!
# Трябва fastbootd (НЕ обичайния fastboot режим)
fastboot reboot fastboot    # или: fastboot reboot-fastboot (може да трябва 2 пъти)

# 4. Flash recovery на ДВЕТЕ слотове
fastboot flash recovery_a DODO-recovery.img
fastboot flash recovery_b DODO-recovery.img

# 5. Рестартирай в recovery
fastboot reboot recovery

# 6. В recovery: Factory Reset → Format data/factory reset

# 7. Sideload ROM-а
adb sideload lineage-22.2-DODO-billie2.zip

# 8. Рестартирай системата
```

> ⚠️ `fastboot flash recovery` ще гърми с грешка — партицията се казва `recovery_a`/`recovery_b`, не просто `recovery`.

> ⚠️ Ако след flash на OOS или MSM Tool bootloader-ът се заключи пак, повтори `fastboot flashing unlock`.

> ⚠️ Ако `/data` е в невалиден формат (UT), recovery може да зависи. Fix от recovery shell:
> ```bash
> make_f2fs -g android /dev/block/by-name/userdata
> dd if=/dev/zero of=/dev/block/by-name/metadata bs=4096 count=256
> ```

## Диагностика при черен екран

Ако OS boot-ва (чуваш звуци, USB показва MTP/ADB), но екранът е черен — включи adb диагностика в build-а:

```makefile
# vendor/dodo/dodo.mk
PRODUCT_PRODUCT_PROPERTIES += \
    persist.sys.usb.config=adb \
    ro.adb.secure=0
```

После build-ни и флашни, след което:
```bash
# Провери crash log-овете
adb shell logcat -b crash

# Събуди дисплея
adb shell input keyevent KEYCODE_WAKEUP

# Виж какво прави системата
adb shell dumpsys activity | grep -E "mResumed|top"
adb shell dumpsys user | grep -A5 "UserInfo{"

# Kernel log (за driver проблеми)
adb shell dmesg | grep -iE "wlan|icnss|cnss"
```

## Известни проблеми

### WiFi не работи

**Статус:** Частично решен — модулът се зарежда (`lsmod` показва `wlan 7696384 2`), `/dev/wlan` съществува, `icnss` успешно инициализира. НО:
- При `svc wifi enable`: само 2 реда в dmesg, `hdd_driver_load()` не се вика
- Грешки: `"Failed to initialize firmware mode controller"`, `"cds_get_context: Module ID 51 context is Null"`
- `wlan0` интерфейсът никога не се създава

**Вероятна причина:** Липсващи WLAN board-data файлове (`bdwlan*.bin`) в `/vendor/firmware/wlan/qca_cld/`. Тези файлове са device-специфична калибрация на WiFi антената и трябва да се извлекат от официалния OxygenOS 11.0.15 vendor образ.

**Следващи стъпки за решаване:**
1. Извлечи `vendor.img` от OOS 11.0.15 и намери `bdwlan*.bin` файловете
2. Добави ги в `vendor/oneplus/billie2/proprietary/vendor/firmware/wlan/qca_cld/`
3. Rebuild + flash

### Samsung-стил off-mode зареждане

Не е имплементирано — изисква промени в ramdisk/charger бинарния и animation assets.

### Lawnchair като default launcher

Lawnchair е инсталиран, но не е зададен като default. Нужен е overlay за `config_defaultHome`.

## Swap за билд на слаба RAM машина

LineageOS build изисква много RAM. С 14GB RAM добави swap:

```bash
sudo fallocate -l 24G /swapfile-dodo
sudo chmod 600 /swapfile-dodo
sudo mkswap /swapfile-dodo
sudo swapon /swapfile-dodo
# За постоянно (в /etc/fstab):
echo '/swapfile-dodo none swap sw 0 0' | sudo tee -a /etc/fstab
```
